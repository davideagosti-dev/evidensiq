## Why Funding May Be Needed

Open infrastructure projects require sustained effort beyond the completed Phase 1 specification and Phase 2 TypeScript reference implementation:

- Specification maturation and community review
- Interoperability and cross-implementation conformance
- Reference implementations in multiple ecosystems
- Documentation and examples
- Conformance and evaluation tooling
- Security research and review
- Adapter development and maintenance
- Community support and contributor onboarding

Volunteer maintainer effort can carry early phases, but maturation benefits from dedicated, funded work.

## Potential Use of Future Funding

Funding should support **project-related work and public project outcomes**. Potential allocations include:

### Specification Design

- Maturing the business context model based on community feedback
- Versioning, migration guides, and backward compatibility
- RFC process and structured community input

### Reference Implementations

- Portable Context Consumption work building on the TypeScript reference implementation
- Additional cross-runtime reference implementations, potentially including .NET
- Shared conformance suites across implementations

### Documentation and Examples

- Expanded reference scenarios
- Integration guides for agent frameworks
- Adapter author documentation

### Interoperability Adapters

- Document ingestion adapters
- CRM and ERP connectors (community or funded)
- Export/import tooling for common platforms

### Conformance and Evaluation

- Conformance test suites
- Evaluation methodology implementation
- Counterfactual testing tooling
- Benchmark scenarios

### Security Research

- Threat model refinement
- Prompt injection mitigation patterns
- Provenance validation research
- Security review of reference implementations

### Community Maintenance

- Issue triage and contributor support
- Governance process maturation
- Community events or working groups

### Maintainer and Contributor Support

- Part-time or full-time maintainer capacity
- Contributor grants for significant features
- Documentation and outreach

## Funding Principles

Any future funding arrangement should adhere to:

1. **Public outcomes** — Funded work produces open, publicly available artifacts
2. **No vendor capture** — Funding must not compromise provider neutrality
3. **Transparency** — Funding sources and allocations are documented publicly
4. **Specification integrity** — Funders do not control semantic invariants or governance unilaterally
5. **No speculative promises** — Funding supports defined work; delivery timelines are not guaranteed prematurely

## Fiscal Hosting

EvidensIQ is fiscally hosted by [Open Source Europe](https://opensourceeurope.org/).

The live EvidensIQ collective is available at [opencollective.com/evidensiq](https://opencollective.com/evidensiq).
